## What Setu is

Setu (सेतु, "bridge") is a 3D decision-support simulator for Himalayan road networks. It shows which villages get cut off when roads fail (landslide, flash flood), how far the nearest working clinic becomes, and what a district control room should pre-position. A narrow valley corridor of Uttarakhand is modelled on real terrain and real roads. Events are triggered by tapping the map.

Built for SCERT Uttarakhand Hackathon 3.0. Deadline for the idea submission: 31 Oct 2026.

It is a simulator for illustration and planning discussion. It is not an operational warning system, and nothing in the UI may imply otherwise.

## Working agreements

1. **Docs first.** Behaviour changes start with a SPEC or ARCHITECTURE edit, then code.
2. **No fabricated data shown as real.** Anything modelled must be labelled as an assumption in the UI and in `web/src/sim/assumptions.ts`. See RULES P1.
3. **The LLM never computes or invents numbers.** It only narrates numbers produced by the simulation. See RULES P2.
4. **The sim core is pure.** `web/src/sim/` must not import React, three.js, or touch the DOM. See ARCHITECTURE.
5. **Ask before adding a dependency.** Justify it in `docs/DECISIONS.md`. Prefer the platform and what is already installed.
6. **Do not edit `data/raw/`.** It is immutable input. Processed data is regenerated by `pipeline/`, never hand-edited.
7. **Keep changes small and reviewable.** One concern per commit. Conventional commit messages (see RULES).
8. **No placeholder UI.** No emojis, no buttons that do nothing, no lorem ipsum, no decorative widgets. Every control is wired or removed.
9. **Verify, then claim.** Do not state that a dataset, API, or behaviour exists or works until it has been checked. Record unverified items as UNVERIFIED.

## Stack (decided)

- Web: React + TypeScript (strict) + Vite, react-three-fiber / three.js, Zustand for state
- Simulation: pure TypeScript, run in a Web Worker
- Data pipeline: Python, offline, outputs static assets consumed by the web app
- LLM brief: small serverless function (Netlify Functions) acting as a proxy; the API key never reaches the client
- Tests: Vitest for the sim core and pipeline-output validators
